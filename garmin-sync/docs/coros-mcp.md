# COROS MCP — заметки по фиче-парити с garmin-sync

Статус: исследование, реализация не начата. Проверено 2026-11-11 по доке
COROS (`support.coros.com`, раздел «API и MCP-соединения») и исходнику
`github.com/coroslab/COROS-MCP` (`docs/en/tools.md`, `docs/en/faq.md`,
`docs/en/getting-started.md` — читал через `gh api`, не только маркетинговую
страницу).

Итог: **COROS MCP закрывает все три задачи**, которые сейчас решает
`garmin-sync` — подключение пользователя, загрузка его тренировок, отправка
тренировки в аккаунт (на часы — при следующей синхронизации устройства, как
и у Garmin). Технически это не REST-библиотека вроде `garminconnect`, а
полноценный MCP-сервер — потребуется свой OAuth 2.0 клиент и свой MCP-клиент
в бэкенде, а не просто HTTP-вызовы.

## Три уровня доступа у COROS

- **Tier 1** — личный коннектор в Claude/ChatGPT (`support.coros.com/hc/ru/articles/50841795180948`).
  Не наш случай: это для человека внутри чужого AI-чата, не для серверной интеграции.
- **Tier 2 — то, что нужно нам** (`support.coros.com/hc/ru/articles/53181619102996`,
  «Разработка на платформе COROS MCP»): свой сервис реализует OAuth 2.0 и
  MCP-клиент, каждый пользователь авторизует свой аккаунт COROS.
  **Самообслуживание, заявка не нужна.**
- **Tier 3** — Partner API (вебхуки, двусторонняя синхронизация, GPX) — не
  нужен для трёх наших задач.

## 1. Подключение пользователя

Стандартный OAuth 2.0, endpoint `https://mcp.coros.com/mcp` (региональные
алиасы `mcpeu.coros.com` / `mcpus.coros.com` / `mcpcn.coros.com` — на случай,
если редирект по основному домену не сработает у не-браузерного клиента).

- Access-токен — 30 дней, refresh-токен — 180 дней, каждый refresh выдаёт
  новый refresh-токен (`docs/en/faq.md`, п.11). В отличие от `garminconnect`
  (сам обновляет токен при каждом логине), здесь обновление — наша
  ответственность, нужна отдельная джоба.
- **Не выяснено:** механика регистрации OAuth-клиента (`client_id`/
  `redirect_uri`) нигде явно не описана — ни в доке поддержки, ни в
  GitHub-репо (там только consumer-инструкция «добавь коннектор в
  Claude/ChatGPT»). Фраза «не требуется ни приложение, ни одобрение»
  намекает на Dynamic Client Registration (RFC 7591 — стандартная практика
  для MCP-авторизации), но это не подтверждено документацией. Проверяется
  на практике: либо найти отдельную dev-доку, либо попробовать
  `.well-known/oauth-authorization-server` на `mcp.coros.com`.

## 2. Загрузка тренировок пользователя

Инструменты (`docs/en/tools.md`, раздел Activities):

- `querySportRecords` — список/поиск активностей по дате, виду спорта,
  дистанции, длительности, темпу, локации.
- `getActivityDetail` — подробные метрики одной активности.
- `queryActivityLapData` / `queryCustomActivityLapData` — круги/сегменты,
  включая произвольное окно времени (например, последние 5 минут).
- `downloadActivityFitFiles` — сами `.FIT`-файлы (до 10 за вызов) или
  `queryActivityFitFileDownloadUrls` — ссылки на скачивание, если клиент не
  принимает файлы напрямую.

**Лимит:** 50 файлов в сутки **на одного авторизованного пользователя
платформы** (не общий на приложение) — `docs/en/faq.md` п.9 явно уточняет
«per connected platform user». Для личного/небольшого масштаба — некритично,
аналогично тому, как уже работает `garmin-sync`.

## 3. Отправка тренировки (аналог `app/workout_builder.py`)

Инструменты (`docs/en/tools.md`, раздел Training):

- `createSingleWorkout` — создать и сохранить в библиотеку.
- `createScheduledWorkout` — создать и сразу поставить в календарь на дату
  одним вызовом (от сегодня до +90 дней) — у Garmin для этого два отдельных
  вызова (`upload_running_workout` + `schedule_workout`).
- `scheduleWorkout` / `updateWorkoutDetails` / `updateScheduledWorkout` —
  поставить существующий воркаут на дату / отредактировать.
- `createTrainingPlan` / `updateTrainingPlan` — план на 4–16 недель.

Виды спорта при создании: **running, cycling, trail running** — то же
ограничение, что уже принято для Garmin (у нас тоже только бег). Плавание и
силовые можно только читать, не создавать.

Как и у Garmin: тренировка попадает в облако/библиотеку COROS сразу, на часы
— при следующей синхронизации устройства с приложением COROS. Прямого push
на устройство через API нет (явно описано для `uploadRouteFile`: «после
импорта синхронизируйте маршрут с часами через приложение COROS»; для
воркаутов текстом не повторено, но механика наверняка та же — считать не до
конца подтверждённым нюансом, не фактом).

Удаление воркаутов/планов через API не предусмотрено — только вручную в
приложении COROS (то же ограничение уже принято для Garmin).

## Чем реализация будет отличаться от garmin-sync

`garminconnect` — обычная Python REST-библиотека (`pip install`, простые
HTTP-вызовы, токен обновляет сама). COROS MCP — полноценный MCP-сервер:
чтобы дёргать его из бэкенда (а не через личный чат в Claude/ChatGPT), сервис
должен сам стать MCP-клиентом:

1. Свой OAuth 2.0 authorization-code flow (редирект пользователя на COROS,
   приём колбэка, хранение access+refresh токенов по `user_id` — как сейчас
   `garmin_tokens.json`, но без автообновления из библиотеки).
2. MCP-клиент поверх `https://mcp.coros.com/mcp` (или региональный адрес) с
   Bearer access-токеном — можно взять официальный `mcp` Python SDK
   (клиентская сторона по HTTP/SSE) вместо самодельного JSON-RPC.
3. Новый сервис (или модуль в `garmin-sync`) по аналогии с
   `app/garmin_client.py` + `app/workout_builder.py`, но под модели данных
   COROS — поля `course`/`sections`/`sportType` не совпадают 1:1 с моделями
   `garminconnect.workout`, нужно замапить отдельно (см. `createSingleWorkout`
   /`createScheduledWorkout` в `tools.md`).

## Рекомендация

Технически COROS MCP закрывает все три пункта и даже local-first удобнее по
части «создать + запланировать одним вызовом». Главная неопределённость —
механика регистрации OAuth-клиента и точный формат полей воркаута/плана; их
придётся изучить на практике при первом вызове `createSingleWorkout` —
аналогично тому, как для Garmin сверяли поля по исходнику библиотеки, а не
только по доке.

Если решим делать интеграцию — первый шаг не писать код сразу, а: (1) взять
тестовый COROS-аккаунт, (2) вручную пройти OAuth через
`https://mcp.coros.com/mcp` curl'ом/Postman и увидеть реальный endpoint
регистрации клиента и формат токен-ответа, (3) сделать один вызов
`createSingleWorkout` с минимальным телом и посмотреть на реальный
ответ/ошибку валидации.
